# 臂上相机标定操作指南 (Eye-in-Hand)

## 用来干什么

相机装在机械臂末端时，把相机看到的坐标转换成机械臂知道的坐标。

```
相机看见 ArUco 标记 → T_cam_marker （相机坐标）
机械臂读出末端位姿 → T_base_ee    （基座坐标）
                      ↓
              T_base_cam = T_base_ee × T_ee_cam
```

**臂上标定**就是找出 `T_ee_cam`（相机在末端坐标系中的位姿），
得到一个 4×4 矩阵，存到 `eye_in_hand_calib.txt`。

---

## 准备工作

### 硬件

| 物品 | 说明 |
|------|------|
| D405 摄像头 | 固定在机械臂末端，随臂移动 |
| ArUco 标记 | 打印一个，贴在硬纸板上，**固定在桌面** |
| 机械臂 | 开机，能切换到**拖拽模式（手扶示教）** |

> **★ 不需要笔尖碰标记！** 标定全程标记不动、机械臂摆位姿即可，
> 相机保持 10~25cm 距离看清标记。

### 确认文件

```bash
ls -la camera_calib.json    # 必须存在（存的是 D405 内参）
ls -la markers/             # 必须有 ArUco 标记图片
```

### 安装依赖

```bash
pip install opencv-python opencv-contrib-python numpy PyYAML
```

### 测试通信

```bash
python3 calibrate_eih.py --robot-ip 192.168.32.101 --dry-run
# 或先连一下看 TCP 是否可读（用任意脚本的 --robot-ip 参数）
```

机械臂通信走 JSON-RPC，**端口 30004**（不是 8899）。

## 操作流程

### 第 1 步：运行标定程序

```bash
python3 calibrate_eih.py --robot-ip 192.168.32.101 --camera-id <ID> --marker-size 0.048
```

> **必须传 `--marker-size`！** 标定用的是**大标记**，黑边实测约 48mm，
> 所以传 `--marker-size 0.048`。默认值 0.02（20mm）是给画布检测时
> 纸上 4 角的小标记用的——标定阶段如果忘记传这个参数，位置误差会
> 有十几毫米（程序会自动反推并警告）。

如果只是看流程：

```bash
python3 calibrate_eih.py --robot-ip 192.168.32.101 --dry-run
```

### 第 2 步：采集位姿（重复 6~8 次）

每次都做同样的事：

```
1. 标记固定桌面（整个标定过程不能移动!）

2. 机械臂切到拖拽模式，把臂拖到标记上方

3. 调整位姿让标记在画面中清晰可见
   距离保持 10~25cm，角度/远近每处都不同

4. 按 [Space] 记录
   → 程序自动读两个值：
      机械臂：当前 TCP 位姿 T_base_ee
      摄像头：标记位姿 T_cam_marker
   → 屏幕显示 "第 1 组" "第 2 组" ...
   → 满 3 组后，每次采集完自动打印**实时质量报告**
```

**实时质量报告怎么看：**

```
  ┌─ 实时质量 (4 组)
  │  旋转轴分布: x=0.54 y=0.40 z=0.06  ✓ 合理
  │  一致性误差: 位置 0.0 mm, 旋转 0.1°
  └─
```

- **旋转轴分布**：x/y/z 三个方向都有分量（如 0.4/0.3/0.3）说明位姿多样，
  数据健康；如果第一项 > 0.85（如 x=1.00），说明所有位姿几乎绕同一方向转，
  旋转解不可靠——**继续采同样的位姿也没用**，必须换朝向。
- **一致性误差**：旋转 < 2° 就可以准备收工了；> 5° 程序会提示换个朝向。

**采集技巧（决定标定质量）：**

| 要求 | 原因 |
|------|------|
| 6~8 个位姿 | 太少算不准 |
| 角度变化大（俯仰/侧倾/旋转） | AX=XB 需要旋转信息约束 |
| 远近都要有（10~25cm 内变化） | 约束平移分量 |
| 不要都在同一个朝向 | 退化成点对应，解不出旋转 |

好的分布示例：

```
正上方 俯视  →  右侧 45°  →  左前 30°  →  近处 12cm
远处 22cm   →  旋转 90°   →  抬高仰角  →  降低俯角
```

想中途检查数据：按 `d` 保存到 `eye_in_hand_calib_data.npz`，之后可离线分析：

```bash
python3 analyze_eih_data.py eye_in_hand_calib_data.npz
```

### 第 3 步：完成标定

按 `c` 键。

程序自动计算并显示：

```
  ┌─ 结果: T_ee_cam
  │  R: [[ 0.99,  0.01,  0.05],
  │      [-0.01,  0.99, -0.02],
  │      [-0.05,  0.02,  0.99]]
  │  t: [0.08, -0.01, 0.05]
  │  位姿一致性: 平均位置误差 1.23 mm, 平均角度误差 0.42°
  │  最大位置误差: 2.10 mm
  └─
```

**判断标定质量（位置一致性 = 标记在基座中的位置是否恒定）：**

| 平均位置误差 | 平均角度误差 | 评价 |
|------|------|------|
| < 5 mm | < 1° | 优秀，可以直接用 |
| 5–15 mm | 1–3° | 可用，可以再采几个位姿优化 |
| > 15 mm 或 > 5° | — | 重新做，检查位姿分布是否太集中 |

确认后保存，得到 `eye_in_hand_calib.txt`。

## 常见问题

### Q: 标记被机械臂挡住了？

**必须调整位姿让标记重新可见再采集。** 臂上相机不能使用缓存——
A（TCP）和 B（标记位姿）必须同一时刻读取，否则标定方程会被污染
（这是固定相机版本才有的能力，eye-in-hand 没有）。

### Q: 太近看不到标记 / 画面模糊？

D405 最佳距离 7~30cm。**保持 10~25cm**，太近失焦、太远识别不了。

### Q: 标定完一致性误差大？

- 检查标记在标定过程中是否被碰动过
- 位姿角度变化是否足够大（全是正上方俯视会退化）
- 距离是否在 D405 最佳区间

### Q: 连不上机械臂？

- 确认控制器 IP（本机示例 192.168.32.101）
- 端口是 **30004**，不是 8899
- 先 ping 通，再试 `--robot-ip` + `--dry-run`

## 标定完成后

用 `aruco_eih.py` 验证并生成画布标定：

```bash
# 方式 A：预览（不保存）
python3 aruco_eih.py --robot-ip 192.168.32.101 --camera-id <ID> --dry-run

# 方式 B：生成画布标定文件（给 RobRoss ROS 2 用）
python3 aruco_eih.py --robot-ip 192.168.32.101 --camera-id <ID> --robross
```

看到机械臂移动到纸面上方、绿色四边形框出绘图区域 → 标定成功。

```
标记固定 → 拖臂摆 6~8 个位姿按 Space → 按 c 完成
```
